# CAPO v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a CLI plus Claude Code and Codex plugins that run one agent team across both platforms and move the whole team to the other platform, from Markdown checkpoints, when the active platform hits its usage limit.

**Architecture:** A single detached Node process (the orchestrator) owns a run. It launches one root session and N coordinator sessions on the *active* platform through an adapter, streams their events, and watches for a `usage-limit` event. On a limit it asks every session for a checkpoint, kills them, flips `activePlatform`, and relaunches the same roles on the other platform with each session's checkpoint as context. All durable state is `state.json` (atomic rewrite) plus immutable Markdown checkpoint sets under `.capo/runs/<run-id>/`. The CLI and both plugins are thin clients over that directory and process. Each plugin is a skill telling the host how to drive the bundled CLI, not a second implementation.

**Tech Stack:** TypeScript 5.7 (ESM, NodeNext) on Node >= 20; npm workspaces; vitest for tests; esbuild for plugin bundles; `yaml` for config parsing; `zod` for config validation; `node:util.parseArgs` for CLI args; git worktrees driven by `execFile`, no git library.

**Spec:** `docs/architecture.md` (v0.1 scope). `docs/roadmap.md` is explicitly out of scope.

## Global Constraints

- Node >= 20.0.0. Repo is developed on v23.11.0. Do not use APIs newer than Node 20.
- TypeScript ESM only: `"type": "module"`, `moduleResolution: "NodeNext"`, all relative imports carry a `.js` extension.
- Runtime dependencies are limited to exactly: `yaml` and `zod`. Dev dependencies limited to: `typescript`, `vitest`, `esbuild`, `@types/node`. Adding any other dependency requires changing this plan first. CAPO ships no MCP server in v0.1: the CLI is the interface and each plugin is a skill that documents it.
- No network calls in any test. Platform adapters are exercised through the fake adapter or through recorded fixture streams.
- Never write secrets, tokens, or resolved credentials into `.capo/`. Platform auth is whatever `claude` and `codex` already have.
- Every commit message ends with a blank line then `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- Tests live beside their source as `*.test.ts`. Run with `npm test` from the repo root.
- Public exports of `@capo/core` are re-exported from `packages/core/src/index.ts`. Other packages import only from `@capo/core`, never deep paths.
- Platform CLI versions verified on this machine: Claude Code 2.1.236, codex-cli 0.147.0.

- [ ] **Step 3: Implement the schema**

`schema.ts` defines a zod schema over the *snake_case wire shape* and nothing else. Key points: `version: z.literal(1)`, `platforms: z.record(z.object({ driver: z.string().min(1) }))`, `models: z.object({ root: z.record(z.string()), coordinator: z.record(z.string()), worker: z.record(z.string()) })`, `start_on: z.string()`, `roles: z.object({ root: z.string(), coordinator: z.string(), worker: z.string() })`, `context: z.array(z.string()).default([])`, `coordinators: z.array(z.object({ id: z.string().min(1) })).min(1)`, `tasks: z.array(z.object({ id: z.string().min(1), coordinator: z.string(), brief: z.string(), write_scope: z.array(z.string()).min(1) })).default([])`, `limits: z.object({ max_workers_per_coordinator: z.number().int().positive().default(2) }).default({})`. Use `.strict()` on every object so unknown keys are rejected.

- [ ] **Step 4: Implement the loader**

`load.ts` does, in order: read the file; `parse(text)` from `yaml` for `.yaml`/`.yml`, `JSON.parse` otherwise; run the zod schema and convert any `ZodError` into a `CapoError` listing `issue.path.join('.')` and `issue.message`; check `start_on` is a key of `platforms`; check every role in `['root','coordinator','worker']` has a model entry for every platform key; check coordinator ids are unique; check each task's `coordinator` exists and task ids are unique; resolve `workspace`, `objective`, every `roles` value, every `context` entry and every task `brief` with `resolve(dirname(configPath), value)`; `stat` each resolved file and throw naming the missing path; normalize each write scope to a workspace-relative POSIX path ending in `/`, reject any that escapes via `..` or resolves outside `workspace`, and reject any pair where one is a prefix of the other; return `Object.freeze(cfg)`.

Use this helper for overlap so the semantics are exact:

```ts
function overlaps(a: string, b: string): boolean {
  return a === b || a.startsWith(b) || b.startsWith(a);
}
```

Scopes are normalized with a trailing slash before comparison so `src/ab/` does not match `src/a/`.

import { mkdtemp, rm, readdir, readFile } from 'node:fs/promises';

import { join } from 'node:path';
import { StateStore, readState, allocateRunId, runDir } from './store.js';
import type { RunState } from '../types.js';

let dir: string;
const base = (): RunState => ({
  version: 1, runId: 'r1', activePlatform: 'claude', status: 'running',
  pauseCount: 0, baseCommit: 'abc', sessions: {}, tasks: {}, limits: {},
  startedAt: new Date().toISOString(), updatedAt: new Date().toISOString(),
});

beforeEach(async () => { dir = await mkdtemp(join(tmpdir(), 'capo-state-')); });
afterEach(async () => { await rm(dir, { recursive: true, force: true }); });

describe('StateStore', () => {
  it('creates, persists and reopens', async () => {
    const s = await StateStore.create(dir, base());
    await s.update(d => { d.activePlatform = 'codex'; });
    const reopened = await StateStore.open(dir);
    expect(reopened.get().activePlatform).toBe('codex');
  });

  it('get() returns a clone that cannot mutate stored state', async () => {
    const s = await StateStore.create(dir, base());
    s.get().activePlatform = 'mutated';
    expect(s.get().activePlatform).toBe('claude');
  });

  it('bumps updatedAt on every update', async () => {
    const s = await StateStore.create(dir, base());
    const before = s.get().updatedAt;
    await new Promise(r => setTimeout(r, 5));
    await s.update(d => { d.status = 'waiting'; });
    expect(s.get().updatedAt > before).toBe(true);
  });

  it('serializes concurrent updates without losing any', async () => {
    const s = await StateStore.create(dir, base());
    await Promise.all(

    expect(files.filter(f => f.includes('.tmp'))).toHaveLength(0);

  it('writes readable indented JSON', async () => {
    await StateStore.create(dir, base());
    expect(await readFile(join(dir, 'state.json'), 'utf8')).toContain('\n  "runId"');

  it('open() on a missing directory throws a CapoError with a hint', async () => {

  });

- [ ] **Step 4: Implement the switch loop**

The state machine, precisely:

1. `start()` resolves `headCommit`, records `baseCommit`, creates a worktree per configured task, seeds `state.tasks`, then calls `#launchAll(platform, checkpoints?)`.
2. `#launchAll` starts the root first, then every coordinator, recording each `SessionRecord`. For each session it spawns a pump that iterates `session.events()` and forwards to `#onEvent`.
3. `#onEvent` on `usage-limit`: record the limit in state with `detectedAt` and `resetAt`, then call `#beginSwitch('usage-limit')`. Every other event kind is logged and, for `error` with `retryable: false`, marks the session failed.
4. `#beginSwitch` is guarded by a `#switching` flag so concurrent limits collapse into one switch. It sets status `switching`; sends `CHECKPOINT_REQUEST` to every live session and collects replies with a 60s per-session timeout; any session that fails to answer gets a minimal checkpoint synthesized from state so the switch never blocks on a dead session; increments `pauseCount`; writes the checkpoint set; closes every session; picks the target platform as the other declared platform that is not currently capped.
5. If no target is available, set status `waiting`, emit `waiting`, and schedule a resume for the earliest `resetAt` (or do nothing and wait for `capo resume` when no reset time is known). Do not relaunch.
6. Otherwise set `activePlatform` to the target, call `#launchAll(target, checkpoints)`, set status `running`, emit `switched`.

A platform counts as capped when `state.limits[p]` exists and either has no `resetAt` or a `resetAt` in the future.

## Execution waves

Tasks within a wave touch disjoint files and can run in parallel. Each wave gates on the previous one.

| Wave | Tasks | Agents |
|------|-------|--------|
| 0 | 1 (scaffold + contract) | lead session, not delegated |
| 1 | 2, 3, 4, 5, 6 | 5 parallel |
| 2 | 7, 8, 9 | 3 parallel |
| 3 | 10, 11 | 2 parallel |
| 4 | 12, 13 | 2 parallel |
| 5 | 14 | 1 |

Wave 1 tasks all depend only on `types.ts`. Wave 2's adapters depend on the conformance suite from Task 6; the orchestrator depends on Tasks 2 through 6 and is tested entirely against the fake adapter, so it does not wait on the real adapters. Wave 3 depends on the orchestrator; Task 11 touches only `core/src/integrate/`, which is disjoint from `packages/cli`. Task 13 needs the real adapter classes only for the registry, not for its assertions.

- `npm test` green; `npm run typecheck` clean.

- The acceptance test proves a limit-triggered switch with checkpoint continuity.
- One live run against real Claude Code and real Codex accounts, switching at least once, before v0.1 is tagged. This is the only step that cannot be automated, and it is the one that matters.
